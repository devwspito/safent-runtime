# Community — real macOS DEBUG verification, 2026-09-12

## Verdict and boundary

The actual Tauri application compiled and ran visibly on macOS 15.5 (24F74),
Apple Silicon, using WKWebView and native Rust commands. This was **not Chrome**
and no Tauri IPC was mocked. The CLI and loopback HTTP/LLM data were explicitly
fictional: this validates native presentation, subprocess/ticket transport and
UI recovery, **not a deployed runtime, Hermes execution or approval authority**.

Release is NOT certified: the macOS shell-adapter integration suite has 12
timeouts, described below; real packaged CLI/Podman, providers, signing and
updater remain release gates. No OCI image, DMG, signed release or publication
was produced. No personal Safent installation or system settings were changed.

Source base: `a1d27c1` plus the copy/test/QA fixture in this cut and the two
tracked renderer outputs regenerated by the normal build. Other agents' Runtime
work, particularly Ads policy/bundle/application, was not changed.

## Reproduction without a live runtime

1. Build `frontend` and `desktop` with their existing npm scripts. Create an
   isolated root using `mktemp -d /tmp/safent-native-macos.XXXXXX`. Do not use a
   real profile or credential. Keep the printed path for cleanup.
2. Copy `desktop/` into that root (exclude node_modules, target, .git). Use an
   existing Rust toolchain or install official rustup there with both
   `RUSTUP_HOME=<root>/rustup` and `CARGO_HOME=<root>/cargo`, `--no-modify-path`,
   after verifying the official rustup-init SHA256. This run used those two
   official static.rust-lang.org files and checksum verification returned OK.
3. In copied `desktop/src-tauri`, run with those environment variables:

   ```sh
   CARGO_TARGET_DIR=<root>/target \
   TAURI_CONFIG='{"identifier":"com.safent.qa.native20260912","productName":"Safent QA"}' \
   <root>/cargo/bin/cargo build --locked
   ```

4. Start the versioned fixture (separate terminal; it prints its random port):

   ```sh
   /usr/bin/python3 desktop/scripts/native-macos-fixture.py --serve \
     --state <root>/state --frontend <runtime>/frontend/dist
   ```

5. Wrap the DEBUG binary in `<root>/Safent QA.app/Contents/MacOS/safent-desktop`.
   Add a minimal Info.plist with CFBundleExecutable `safent-desktop`,
   CFBundleIdentifier `com.safent.qa.native20260912`, CFBundleName `Safent QA`,
   CFBundlePackageType `APPL`, CFBundleShortVersionString `0.9.0`, and
   NSHighResolutionCapable true. Its LSEnvironment must include
   `SAFENT_STATE_HOME=<root>/state`, `SAFENT_PODMAN_PATH=/usr/bin/false`,
   `SAFENT_ENGINE_DIGEST=sha256:fixture-only`, and
   `SAFENT_CLI_PATH=<root>/fixture-cli`. Copy the versioned Python fixture to
   that last path and make it executable. For the missing-CLI case, temporarily
   move only this disposable copy aside. Do not modify a user app bundle.
6. Launch this .app via the native app tool. The default slow mode permits
   Cancel/Retry; use the loopback control, never a provider API:

   ```sh
   curl -sS -X POST http://127.0.0.1:<port>/__qa/control \
     -H 'Content-Type: application/json' -d '{"mode":"ready"}'
   ```

   `model:true` enables fictional model metadata, `approval:true` a fictional
   permission card, and `reconnect:true` returns 401. Set `reconnect:false`
   then click Retry for recovery. No control request executes an actual model,
   advertising action, container or shell command. Unknown API operations
   return 503; these are intentional fixture boundaries, not a working service.
7. Interact only with this QA window. `state/requests.jsonl` records POST paths
   without bodies/tokens, enough to confirm cancel/approval delivery. Close the
   app and terminate only this fixture's recorded PID when finished.

Actual disposable root was `/tmp/safent-native-macos.LhfcCk`; server used port
52938. Exported `safent-arranque.json` is retained there. The unique application
identifier separates WKWebView state from Safent, but macOS may retain cache
and native-dialog preferences for that QA identifier outside the temp root;
this report does not claim full system-profile isolation. No broad cleanup or
cache deletion is performed.

At handoff the QA app and fixture server were closed; a process check found no
remaining QA app/server or deliberately launched shell diagnostic process.
